# Ailog 260924-195730 — SMELL-v3: r=1 LoRA BP 趋势 + run_fed 暴露 LoRA 秩

## 概述

新增 `run_fed --lora-r/--lora-alpha`（此前 LoRA 秩硬编码 r=8），并用 **r=1 LoRA + BP** 在 pos_only 位置表、从 base 起训做 16k 趋势实验（r24/c5/l4/lr1e-4），与同配置的 `r=8 全秩`、`r=8 rotate-k1` 三臂对比。结论：**r=1 能训且单调改善（G-PPL 31.4→30.3），约为 r=8 改善幅度的一半；远好于 rotate-k1（≈不动）**。关键变量是「每参数被更新的次数」而非「秩大小」。

## 结论

1. **r=1 可行**：loss -2.8%、G-PPL -3.5%，单调改善、无发散，但受秩1容量限制，约为 r=8 改善幅度的一半（低秩欠拟合，非机制问题）。
2. **r=1 ≫ rotate-k1**：两者每轮都只更 196,608 个参数；差别在更新**频次**——r=1 每轮更同一批（24 次），rotate-k1 每秩只轮到 3 次。说明**每参数更新频次比秩大小更决定收敛**。
3. **通信-精度**：r=1 每轮 0.197M 参数（1/8 of r=8），换来约一半精度提升，是可用的折中点；rotate-k1 性价比最差。
4. r=1 趋势未收敛，正式对比应给更长/更多轮预算。
