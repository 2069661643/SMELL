- **已定位根因**：ZOO 之前全部「平在 ~32」的根因是 **bf16 损失量化**（差分信号 ~1e-6 ≪ 损失量化台阶 0.0156），**不是维度/秩/覆盖率**。

- **正在跑**：BP k 层扫描（GPU2）+ 队列（k=1@1e-3 → TD-2'）。

## 6. 必知陷阱
1. **bf16 损失量化是 ZOO 杀手**：前向 bf16 → 有限差分全被量化；FA2 只支持 bf16/fp16 → 必须走 fp32 SDPA（`OptSdpaAttention`）。
2. **torch 2.1.2 无 fp32+加性 mask 的 mem-efficient kernel** → 掩码式稀疏 O(L²) OOM；dense causal 反而 O(L) 更快。
3. **Jenga `thresh` = 保留 query 块比例**，仅**上半层**剪、末层豁免（与「每 query 块 top-k KV」不同轴）。
4. **predictor 必须加载训练权重**（`load_predictor_weights`），否则随机选择无意义。
5. 层轮转/k=1 在 BP 下就不收敛 → ZOO 更不可能。
6. profiler：driver.log 因 Python 块缓冲会滞后，**看 `metrics.jsonl`**。
